## 四、C 部分：全流程端到端闭环验证

### 4.1 测试驱动方法

- **UIA 无障碍自动化**：Qt 6.8 窗口通过 `System.Windows.Automation` 驱动——`SetFocus()` 聚焦输入框、`InvokePattern` 点击按钮、`WindowPattern.Close()` 关闭窗口、读状态栏 Name 获取临时消息。**全程无需鼠标与前台焦点，对窗口遮挡免疫**。
- **像素探针**：GDI `GetPixel` 断言主题色（`#0E639C` 工控蓝 / `#00E676` 荧光绿 / `#1E1E1E` 暗黑底），按区域统计颜色占比量化渲染结果。
- **ASCII 色块渲染**：全窗口/全屏像素分类降采样，辅助定位控件与观察布局。
- **对抗性处理**：主窗口常被其他窗口遮挡（多任务竞争），像素级断言先 `HWND_TOPMOST` 置顶，并以"侧边栏选中按钮蓝色占比 >30%"作为**真实捕获判定**后重试。

### 4.3 验收中发现并修复的渲染缺陷（1 项）

| 项目 | 内容 |
|---|---|
| 现象 | 状态栏实测蓝色仅占 **8%**，与 README 规格「`#0E639C` 工业深蓝底座」严重不符 |
| 根因 | 全局规则 `QWidget { background-color: #1E1E1E; }` 将 QStatusBar 内部子容器一并染成深色，遮蔽了 `QStatusBar` 的蓝底规则 |
| 修复 | [dark_style.qss](../res/qss/dark_style.qss) 补充：`QStatusBar::item` 与 `QStatusBar QWidget` 均 `background-color: transparent` |
| 复测 | 蓝带占比 **8% → 91.5%**；同时全屏数据：侧边栏选中按钮蓝 90.3%、表格四色委托（蓝 919 / 绿 112 / 黄 112 / 红 140 采样点）、内容区 100% 暗黑主题 —— 全部符合规格 |

### 4.4 性能与稳定性结论

- **万行压测**：数据生成 11ms、视口渲染总耗时 23ms（虚拟化按需渲染，无整表重绘风暴）。
- **无闪烁**：时钟 1s 轮询无横向抖动；数据泵 1s 局部 `dataChanged` 精准重绘（仅温度→内存列区间）。
- **无功能失效**：11 项验收用例全链路闭环通过；两处关闭路径（主窗 / 登录框）均干净退出、无悬挂。

## 五、测试期间沉淀的工程经验（供后续迭代参考）

| 经验 | 说明 |
|---|---|
| Git Bash 下 `make clean` 静默失效 | qmake 生成的 clean 目标调用 cmd 内建 `del`，在 Git Bash 下 CreateProcess 失败且被忽略 → 清理改用 `rm -f build/obj/*.o` |
| make 需显式 PATH | 必须 `export PATH="/d/QT/Tools/mingw1310_64/bin:/d/QT/6.8.3/mingw_64/bin:$PATH"`，否则 g++ 解析到错误编译器（cc1plus 无法执行） |
| 150% DPI 坐标差 | 非 DPI-aware 进程与 Qt 窗口坐标相差 1.5 倍；UIA 坐标恒为物理像素 |
| UIA 命名细节 | checkable QPushButton 暴露为 CheckBox 类型；无障碍名含 emoji 前缀（如「📈 实时曲线」），匹配需用 `Contains` |
| 窗口遮挡对抗 | 像素断言前先 `HWND_TOPMOST`，并用"已知必蓝区域"判定捕获真实性后重试 |

> 上述经验已同步沉淀至长期记忆，下次测试可直接复用。
